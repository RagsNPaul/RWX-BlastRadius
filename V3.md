# V3: cut the board run time in half (331 s → ~165 s)

## The target in numbers
- Board now: **330.3 s simulated + 1.2 s CPU, 0 misses** on ~40 commits = **8.3 s/commit**.
- Half = **~165 s = 4.1 s/commit**. Best possible ≈ 3.2 s/commit. The leader ≈ 3.6 s/commit.
- So V3 must remove about **4 s per commit**. Small tests can't do that. It has to come from:
  1. **"All tests" fallbacks** (36.8 s each): `all:import-line`, `all:import-class`.
  2. **Expensive tests that pass**: test_max_nodes 28.8 s, test_execute_tpcds 21.5 s, test_generator_memory 6.7 s, test_execute_tpch 3.9 s, test_optimized_tpch 3.5 s. One of these in a selection sets the whole commit's cost.

## The risk policy (replaces "zero misses at any cost")
A miss costs 300 s. A rule is worth shipping when it saves more than it risks:

    net = (seconds saved) − 300 × (extra misses), measured on the HOLDOUT test patches

- Keep a rule only if net > 0 on the holdout **and** it adds at most 1 extra miss per 40 holdout patches (≤ 2.5% miss rate). Expected board cost ≈ 7.5 s per 40 commits, which is fine for a rule saving 40+ s.
- Rules must stay general policies (like "skip test X unless the change is in files Y"). **No table from a kind of edit to the tests it breaks**: the contest bans those, and top entries are read.
- Always keep the last safe version as the final entry until a riskier one has scored better on the board **and** on the holdout.

## V3-1: import-time check instead of "all tests" (biggest, safest lever)
> Behind IMPORT_CHECK=1. When a patch would trigger `all:import-line` or `all:import-class`, first run a check in a subprocess (python -S, cwd /tmp, the scorer allows this and charges its CPU). (1) Copy only the sqlglot/ package from /opt/sqlglot to /tmp/s (about 10 MB; /tmp holds 64 MB), apply the patch with our own applier, (2) import every sqlglot module (pkgutil.walk_packages) in that copy, (3) compute an **import fingerprint**: for every class in sqlglot modules, the repr of class-level attributes that are dicts, sets, lists, tuples, str, int, bool or Enum, plus `.sql()` of every class/module attribute that is an `exp.Expr` (the import-time templates like ZIPF_TEMPLATE), plus `exp.ALL_FUNCTIONS` names and every Expression's `arg_types` and `_sql_names`. Precompute the original fingerprint offline into maps/import_fp.json (hash per key). (4) If the patched import fails → all tests (as today). If the fingerprints are identical except for keys inside the edited class → don't use the "all tests" fallback; use the normal line rules plus the class-usage tests for the changed keys only. If anything else differs → all tests. Cache: one check per patch. Report the check's CPU seconds per commit; it must average under 1.5 s. Gate: holdout net > 0, and r7_11 (template breakage) must still select all tests.

## V3-2: checks for the expensive tests (instead of always selecting them)
> Behind EXPENSIVE_CHECK=1. For each selected test over 3 s that was pulled in by coverage (not by a fixture it reads), decide with a cheap check in the same subprocess as V3-1 (reuse the patched copy):
> - **test_execute_tpcds / test_execute_tpch / test_optimized_tpch**: if the patch touches nothing under sqlglot/executor/, optimize every query in the TPC-H/TPC-DS fixtures with the original and the patched sqlglot (same calls the tests make, read tests/test_executor.py and tests/helpers.py for the exact schema and settings) and compare `.sql()` output. All identical → drop these tests. Any difference → keep them. If optimizing all queries costs too much CPU, measure first: precompute offline which fixture queries execute each changed line's file at all and only re-optimize those.
> - **test_max_nodes**: keep only if the patch touches parser.py, tokens.py, tokenizer_core.py, expressions/core.py, or a line that the map says test_max_nodes runs **and** that line is in the default dialect's parse path. Otherwise drop it. This is a policy with risk: EV-gate it.
> - **test_generator_memory**: keep only if the patch touches generator.py or expressions/core.py. EV-gate.
> Print per commit: which expensive tests were dropped and the check's CPU. Gate: holdout net > 0 including the check CPU (CPU counts 1:1 in the score).

## Guardrails that stay on no matter what
- Any exception, failed import or unreadable patch → full suite for that commit.
- Subprocess checks run under a per-commit CPU limit (e.g. 5 s); if hit, use the old, wider selection.
- Total run must finish well under 3 min (4.5 min in the final, ~1.5× the commits): log wall time per commit.
- CPU counts 1:1, so a check only pays when it removes a test that costs more than the check.
